# Roadmap

## Before public launch

- Owner review of the actual build, public fields, source-update guidance and repository contents.
- Recheck live source URLs and appointment conflicts; ask faculty to keep their public profiles/CVs current. Confirm scope/categories, especially cross-college affiliates, practitioners, unknown primary homes and currently missing roster entries.
- Configure and verify periodic automated source refreshes, retaining provenance, consent, validation and publication-approval gates; the cloud workflow is implemented locally; remote authentication, the API key and the first cloud run remain to be verified.
- Review institutional representation, privacy and permitted use of any future branding/assets.
- Confirm repository name/account/visibility, Pages hostname and base path; authorize exact remote operations before doing them.

## Next data improvements

- Complete individual research enrichment across the collected roster; replace directory fallbacks where verified biographies exist.
- Reconcile emeriti, visiting/adjunct lists, affiliated faculty and all centers. Expand explicit research geography from substantive context and record methods consistently.
- Add verified academic background, selected publications and international professional experience without confusing them with research locations.
- Invite self-reported languages with skill-specific proficiency and distinct publication consent. Continue to exclude citizenship from the public product.
- Add controlled topic aliases and near-duplicate suggestions, with human review before merging.

## When justified by use

Add FSU SSO, faculty-owned drafts, secure submissions, administrative review/consent queue and version history through a backend. Retain the current public schema/export as the publication boundary. Schedule modest refreshes with provenance and change review; never publish scraped changes blindly. Improve screen-reader testing and keyboard map controls with actual user feedback.

For other FSU colleges, add college/unit identifiers to the schema and filters, retain stable person IDs and many-to-many affiliations, and use the same evidence/consent model. A hosted database becomes useful only when shared editorial workflows exceed the simplicity of reviewed JSON/CSV.
